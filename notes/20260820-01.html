让 Codex CLI 不再重复询问：双链路 YOLO 配置

一次目录信任提示的排查，最后落到 provider 切换、全权限参数和跨 Windows/Linux wrapper。

Codex CLI、CC Switch、官方 profile 和 RelayQuill 的配置记录。

先判断提示来自哪里

Do you trust the contents of this directory? 不是账号注册提示，也不是普通的沙箱审批。它对应 Codex 对当前 project 或 worktree 的信任记录。记录通常写在 ~/.codex/config.toml 的 projects.*.trust_level 中。

问题出在本机的 wrapper 每次启动前都会切换 provider。切换脚本重新生成配置时，删掉了原来的 [projects.*] 表；本次启动确认 trusted 后，下一次切换又把它删掉，于是每次都像第一次打开。

python "%~dp0cc-switch-codex" relayquill
codex ...

所以要修的不是“注册一次 Codex”，而是 provider 切换时的配置合并逻辑。

把 YOLO、沙箱和目录信任分开

当前 Codex CLI 没有名为 --yolo 的参数。这里把 YOLO 作为目标，把官方支持的强制开关作为实现：

codex \
  --dangerously-bypass-approvals-and-sandbox \
  --dangerously-bypass-hook-trust \
  --config sandbox_mode=danger-full-access \
  --config approval_policy=never \
  --config tui.resume_cwd=current \
  "$@"
  • --dangerously-bypass-approvals-and-sandbox：跳过命令审批并不使用沙箱。
  • --dangerously-bypass-hook-trust：不再为 hook 的持久信任单独询问。
  • tui.resume_cwd=current：resume 使用当前工作目录，避免在当前目录和会话保存目录之间再次选择。
  • projects.<path>.trust_level = "trusted"：处理目录信任；它和沙箱审批不是同一个开关。

切换 profile 时保留信任表

切换脚本需要把新 provider 配置、官方 profile、旧的 live config 合并起来，再写回项目记录。关键部分可以写成：

existing_config = read_text(CODEX)

live = build_provider_config(provider_config)
live = merge_trusted_projects(
    live,
    official_config,
    provider_config,
    existing_config,
)

合并函数不需要扫描整块磁盘。启动前登记当前目录和父目录即可：

def local_trust_roots():
    current = Path.cwd().resolve()
    roots = []
    while True:
        roots.append(str(current))
        parent = current.parent
        if parent == current:
            break
        current = parent
    return roots

父目录记录是为了覆盖 Codex 用 .git 解析出的 project root。它不是通配符；每次从新的目录启动 wrapper 时，脚本会为那棵路径重新登记 trusted。

两条链路只差 provider

Windows 的两个 wrapper 保持同一个权限参数，只在前一步切换不同 profile：

@echo off
setlocal
python "%~dp0cc-switch-codex" codex-official
if errorlevel 1 exit /b %ERRORLEVEL%
codex --dangerously-bypass-approvals-and-sandbox --dangerously-bypass-hook-trust --config sandbox_mode=danger-full-access --config approval_policy=never --config tui.resume_cwd=current %*

RelayQuill 版本只把 codex-official 换成 relayquill。Linux 版本使用同样的参数：

#!/usr/bin/env bash
set -e
python3 "$HOME/.local/bin/cc-switch-codex" relayquill
exec codex \
  --dangerously-bypass-approvals-and-sandbox \
  --dangerously-bypass-hook-trust \
  --config sandbox_mode=danger-full-access \
  --config approval_policy=never \
  --config tui.resume_cwd=current \
  "$@"

官方 Linux wrapper 只需要把 provider 参数改为 codex-official。这样两个入口都可以使用 resume，并且不会因为切换链路而丢掉 trusted 记录。

同步到另一台机器

只同步脚本，不复制认证文件。远端使用自己的 provider 和 API Key：

scp ~/.local/bin/cc-switch-codex A100_154:~/.local/bin/
scp ~/.local/bin/codex-official A100_154:~/.local/bin/
scp ~/.local/bin/codex-relay A100_154:~/.local/bin/
ssh A100_154 'chmod 755 ~/.local/bin/cc-switch-codex ~/.local/bin/codex-official ~/.local/bin/codex-relay'

如果远端是 Python 3.10，tomllib 可能不存在。配置校验可以优先尝试 tomli，没有解析库时不要让这一步阻断 provider 切换；最终配置仍由 Codex 解析。

最短的验证

codex-official --help
codex-relay --help
cc-switch-codex current
grep -E 'projects|trust_level' ~/.codex/config.toml

先验证两个入口能启动，再分别切换一次 profile，确认 trusted 表没有消失。最后再运行 codex-relay resume 或 codex-official resume。

安全

这不是安全加固，而是把交互式安全边界改成了默认放行。全权限模式会允许模型读写工作目录、执行命令并加载 project-local config、hooks 和 rules。真正需要发布代码时，仍应单独检查 wrapper、项目目录和 API Key。

API Key 不要放进文章、脚本、.bashrc 或命令历史。曾经粘贴到聊天或日志里的 Key，应撤销后重新创建。
