GRPO: what changes when the critic disappears

GRPO keeps PPO's clipped update, replaces the learned value baseline with comparisons inside a group, and moves the engineering bottleneck somewhere else.

The equations are short. Their edge cases are not.

1. Replace a critic with a group

For one prompt \(q\), sample \(G\) completions from the old policy:

\[o_1,\ldots,o_G\sim\pi_{\theta_{\mathrm{old}}}(\cdot\mid q).\]

Give each completion a scalar outcome reward \(R_i\). GRPO standardizes rewards within that prompt:

\[\bar R=\frac{1}{G}\sum_{j=1}^{G}R_j,\qquad s_R=\sqrt{\frac{1}{G}\sum_{j=1}^{G}(R_j-\bar R)^2},\qquad \hat A_i=\frac{R_i-\bar R}{s_R}.\]

The same \(\hat A_i\) is assigned to every token in completion \(i\) under outcome supervision. There is no learned state-value model. The baseline is the performance of sibling answers to the same question.

2. The PPO machinery stays

For token \(t\) in completion \(i\), define

\[\rho_{i,t}(\theta)= \frac{\pi_\theta(o_{i,t}\mid q,o_{i,<t})} {\pi_{\theta_{\mathrm{old}}}(o_{i,t}\mid q,o_{i,<t})}.\]

The outcome-supervision objective in DeepSeekMath can be written as

\[\begin{aligned} J_{\mathrm{GRPO}}(\theta)=\mathbb E\Bigg[\frac1G\sum_{i=1}^{G}\frac1{|o_i|} \sum_{t=1}^{|o_i|}\Big(&\min(\rho_{i,t}\hat A_i, \operatorname{clip}(\rho_{i,t},1-\epsilon,1+\epsilon)\hat A_i)\\ &-\beta D_{i,t}\Big)\Bigg]. \end{aligned}\]

So GRPO is not “PPO without everything.” It retains an old policy, importance ratios, clipping, multiple update epochs, and reference-policy regularization. What disappears is the separately trained critic.

3. The KL term is explicit

DeepSeekMath uses the following nonnegative sample estimator for \(D_{\mathrm{KL}}(\pi_\theta\Vert\pi_{\mathrm{ref}})\):

\[D_{i,t}=x_{i,t}-\log x_{i,t}-1,\qquad x_{i,t}=\frac{\pi_{\mathrm{ref}}(o_{i,t}\mid q,o_{i,<t})} {\pi_\theta(o_{i,t}\mid q,o_{i,<t})}.\]

Its nonnegativity follows from \(x-1\geq\log x\) for \(x>0\). The reference model asks the policy not to move too far from its starting behavior, while clipping controls movement relative to the policy that generated the current batch. Those are different comparisons.

4. Group normalization has useful invariances

By construction, the normalized advantages sum to zero:

\[\sum_{i=1}^{G}\hat A_i=0.\]

If rewards undergo a positive affine transformation \(R_i'=aR_i+b\) with \(a>0\), the normalized advantages stay the same, apart from a numerical stabilizer. GRPO therefore cares about relative performance inside the group, not the absolute reward scale.

The baseline is not independent of its own sample. A useful identity is

\[R_i-\bar R=\frac{G-1}{G}(R_i-\bar R_{-i}),\]

where \(\bar R_{-i}\) is the mean of the other \(G-1\) rewards. Using the full group mean mostly changes the scale compared with a leave-one-out baseline, and the standard deviation absorbs much of that scale.

5. The awkward cases matter

  • All rewards tie. Then \(s_R=0\). An implementation needs an epsilon, a skip rule, or both. A tiny denominator can amplify noise.
  • Binary rewards are sparse. A group of all failures gives no relative learning signal, even if every completion is bad in a different way.
  • One reward labels every token. Outcome supervision cannot say which reasoning step caused success or failure. Process supervision can assign step rewards, but it needs a trustworthy process signal.
  • Prompt difficulty changes the signal. Group normalization compares answers to the same prompt, which is useful, but very easy and very hard prompts often produce ties.
  • Long answers get averaged over tokens. The \(1/|o_i|\) factor changes how completion length affects the update. Length and reward should be inspected together.

6. Less critic memory does not mean cheap RL

Removing a value model saves parameters, optimizer state, activations, and critic training work. It also requires multiple completions per prompt. For autoregressive models, generation is often the expensive part.

This matches a broader pattern in my experiment logs across three machines: raw task or environment throughput is a poor substitute for end-to-end learner throughput. In GRPO I would report generation tokens per second, training tokens per second, group reward standard deviation, zero-variance group rate, KL, clip fraction, completion length, and reward by prompt category.

中文小结

GRPO 没有把 PPO 全推翻。它主要是不用 critic，改为同一道题多次采样，再用组内相对奖励当 advantage。省下的是 value model，新增的压力是多次生成。最需要盯的不是一个总 reward，而是组内方差、全员同分比例、KL、clip fraction 和长度分布。
